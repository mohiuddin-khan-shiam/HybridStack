# Partial Dependence Plots (PDP)

## 1. Introduction and Purpose of the Method
A **Partial Dependence Plot (PDP)** is a model-agnostic, global interpretability method designed to visualize the functional relationship between a small subset of input features and the predicted outcomes of a machine learning model. The primary purpose of a PDP is to show how a specific feature (or pair of features) marginally influences predictions—such as demonstrating whether the model's reliance on a variable is linear, monotonic, exponential, or complex and non-linear. By isolating the average marginal effect of a target feature while accounting for the expected values of all other inputs, PDPs help users understand the global behavior of black-box models.

---

## 2. Background and Motivation
Complex machine learning systems, such as deep neural networks or gradient-boosted trees, capture intricate non-linear relationships and high-order feature interactions. However, this expressive power hides the internal mechanisms of the model, making it difficult to understand how specific variables drive predictions. 

To overcome this, Jerome H. Friedman (2001) proposed Partial Dependence Plots as a core diagnostic tool for interpretation. The underlying motivation is to look past localized single-instance variations and capture a stable global trend. PDPs generalize simpler linear coefficients into non-parametric curves, helping developers validate that the model aligns with domain knowledge and behaves predictably across its input range.

---

## 3. Theoretical Foundation
Partial Dependence Plots rely on **marginal integration**. To isolate the relationship between a feature of interest and the model's output, the method averages out the effects of all other independent variables. 

Let $\mathbf{X}$ represent the complete set of input features. We split this feature space into two disjoint subsets:
* $\mathbf{X}_S$: The target subset of features for which we want to evaluate partial dependence (typically containing 1 or 2 variables).
* $\mathbf{X}_C$: The complement set containing all other features in the model.

The full predictive model can be represented as a function $f(\mathbf{x}) = f(\mathbf{x}_S, \mathbf{x}_C)$. The true partial dependence function $f_S(\mathbf{x}_S)$ is mathematically defined as the expected value of the model's predictions over the marginal probability distribution of the complement features $p(\mathbf{x}_C)$:

$$f_S(\mathbf{x}_S) = \mathbb{E}_{\mathbf{X}_C}\left[ f(\mathbf{x}_S, \mathbf{X}_C) \right] = \int f(\mathbf{x}_S, \mathbf{x}_C) p(\mathbf{x}_C) d\mathbf{x}_C$$

---

## 4. Mathematical Formulation and Equations
In practice, the true marginal probability density function $p(\mathbf{x}_C)$ is unknown. We estimate the partial dependence function by calculating a sample average over the training dataset $D = \{\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_n\}$.

The estimated partial dependence function $\hat{f}_S(\mathbf{x}_S)$ at a specific grid coordinate value $\mathbf{x}_S$ is computed as:

$$\hat{f}_S(\mathbf{x}_S) = \frac{1}{n} \sum_{i=1}^{n} f(\mathbf{x}_S, \mathbf{x}_{i,C})$$

Where:
* $n$ is the total number of samples used from the dataset.
* $\mathbf{x}_{i,C}$ represents the actual values of the complement features for the $i$-th sample in the dataset.
* $f(\mathbf{x}_S, \mathbf{x}_{i,C})$ is the prediction generated by the model when the target features are forced to the grid value $\mathbf{x}_S$ while the remaining features are kept at their original values from the $i$-th row.

For a bivariate (two-way) PDP evaluating interactions between two features $j$ and $k$, the function maps across a 2D coordinate grid space:

$$\hat{f}_{\{j,k\}}(x_j, x_k) = \frac{1}{n} \sum_{i=1}^{n} f(x_j, x_k, \mathbf{x}_{i,-{\{j,k\}}})$$

---

## 5. Algorithm and Workflow

1. **Grid Selection:** For each target feature in $\mathbf{X}_S$, extract its empirical range (minimum to maximum) and select a fixed number of evenly spaced evaluation points to create a coordinate grid (defined by `grid_resolution`).
2. **Feature Substitution loop:** For each discrete evaluation point $v$ in the coordinate grid:
    * Create a synthetic copy of the dataset where the values of the target feature $\mathbf{X}_S$ are replaced with $v$ for all rows.
    * Leave all complement feature values $\mathbf{X}_C$ unchanged.
3. **Inference Execution:** Pass the entire modified synthetic matrix through the model's prediction method (`model.predict`) to obtain a vector of predicted values.
4. **Marginal Averaging:** Calculate the arithmetic mean of these predictions across all rows. Store this mean value as the partial dependence score for grid value $v$.
5. **Visualization:** Plot the evaluation grid values on the horizontal axis against the stored average prediction scores on the vertical axis to display the global response curve.

---

## 6. Key Assumptions
* **Feature Independence:** The defining assumption of PDPs is that the target features $\mathbf{X}_S$ are independent of the complement features $\mathbf{X}_C$. If features are highly correlated, the substitution step will create highly unrealistic synthetic data instances. For example, if the model is evaluated with a combination of `Room Temperature = 45°C` and `Heating Status = ON (Maximum)`, but this combination never occurs in reality, the model's prediction on this out-of-distribution instance can skew the average curve and produce a misleading interpretation.

---

## 7. Input and Output Requirements

### Inputs
* **Trained Estimator Instance:** A fitted machine learning model object that implements a standard prediction interface (`predict` or `predict_proba`).
* **Evaluation Matrix:** A tabular dataset (`pandas.DataFrame` or `numpy.ndarray`) used as the baseline distribution to average out the complement features.
* **Target Features List:** A selection of feature indices or names to be plotted on the grid space.

### Outputs
* **PDP Display/Figure Object:** A plot structure mapping the target feature values against the average expected prediction scales.

---

## 8. Advantages and Limitations

### Advantages
* **Intuitive and Interpretables:** The visual curves translate complex non-linear models into clear, easy-to-read lines that map directly back to the target variable's scale.
* **Model-Agnostic:** Can be applied to any supervised machine learning framework.
* **Global Perspective:** Captures an aggregated view of model behavior across the entire data distribution rather than focusing on a single instance.

### Limitations
* **Vulnerable to Correlation Bias:** If features are highly correlated, the grid averaging step introduces out-of-distribution artifacts that can distort the true relationship.
* **Hidden Interaction Effects:** Because PDPs average predictions across all instances, they can mask localized interaction effects. For example, if a feature has a strong positive effect on half the data but a strong negative effect on the other half, the values will cancel out, and the resulting PDP line will appear misleadingly flat.

---

## 9. Common Use Cases
* **Sanity Checking and Model Auditing:** Verifying that a model behaves in accordance with physical laws, economic principles, or business constraints (e.g., ensuring that increasing loan risk scores monotonically decreases approval probabilities).
* **Feature Relationship Diagnostics:** Evaluating whether a fast linear model can replace a slower non-linear model by checking if the PDP response curves are mostly linear.
* **Risk Management and Compliance:** Providing macro-level explanations of model mechanics to external regulators and non-technical stakeholders.

---

## 10. Important Parameters and Their Effects
* `kind`: Can be set to `'average'` for standard PDPs, `'individual'` for Individual Conditional Expectation (ICE) lines, or `'both'`. ICE lines display the model's response curve for each individual instance separately, which helps uncover hidden interactions that standard PDP averaging might mask.
* `grid_resolution`: Defines the number of points evaluated along the feature range. Higher values yield smoother curves but require more model inference calculations, increasing execution time.
* `subsample`: Restricts the calculation to a random subset of rows from the dataset. This bounds execution times when working with large datasets without significantly altering the averaged marginal trends.

---

## 11. Computational Complexity
The computational complexity scales linearly with the number of evaluation points and the size of the dataset. For a single feature with grid resolution $G$ evaluated over a matrix of $n$ rows and $p$ features, the model must perform $G \times n$ total predictions ($O(G \cdot n \cdot \text{Cost}_{\text{predict}})$). If evaluating two-way feature interactions, the complexity increases to $O(G^2 \cdot n \cdot \text{Cost}_{\text{predict}})$.

---

## 12. Best Practices and Practical Considerations
* **Standardize Input Scales:** When plotting multiple subplots together, consider centering the partial dependence lines around zero or a baseline prediction to make it easier to compare the relative impact scales of different features.
* **Use ICE Lines for High Correlation:** If you suspect strong feature interactions or collinearity, configure `kind='both'` to overlay ICE lines on top of the PDP curve. If the individual ICE lines diverge significantly (e.g., some trend up while others trend down), it indicates that feature interactions are present, meaning the aggregated PDP line cannot be interpreted in isolation.
* **Subsample Large Datasets:** To keep computation times manageable on large datasets, subsample the baseline matrix to around $500$ to $1000$ rows. This provides a large enough sample size to reliably average out complement effects while keeping the number of model predictions low.
